# 0010 ELF symbolization

Status: accepted (28 October 2026). Implements F3.5.

## Problem

Firmware prints addresses when it fails: `HardFault: PC: 0x0800412a`. To a person
staring at a terminal that is a number; the useful fact is `src/flight_ctrl.c:184
(pid_update)`. Turning one into the other needs the firmware image, which the team
already has, and a decoder that does not invent a line when the image has none.

## Scope

Loading an image, resolving an address to file, line and function, scanning text
for pointers, and building the editor command. Not in this stage: the file watch
(D-43), `defmt` and `pw_tokenizer` frame decoding (D-42), symbol demangling (D-44),
and wiring badges into the live stream (D-45, which needs the GUI).

## Behavior

1. `ElfImage::load` reads the file once and keeps two views: the function symbols
   from `object`, and the DWARF line table through `addr2line`. ELF, PE and Mach-O
   are all accepted, so the same code runs on a firmware `.elf` and on a host test
   binary.
2. `resolve(address)` returns `Some` only when the line table has an entry. An
   address outside the image's code span returns `None` before the line lookup is
   asked, because a crash log can print any number and the lookup must not be the
   thing that fails.
3. `nearest_function(address)` searches the sorted symbol table and accepts a
   symbol when the address falls inside its recorded size. A symbol with no size
   covers everything up to the next symbol.
4. `scan_pointers(text)` finds `0x` followed by 8 to 16 hex digits at a word
   boundary. Fewer than 8 is a number, more than 16 is something else. A 64-bit
   address printed without leading zeros (`0x140001434`) is found.
5. `Editor::command` builds the string a badge click runs: `code --goto file:line`
   or `clion --line line file`, with the path quoted when it contains a space.
   Running it is the window's job.
6. A file that is not an image is refused with the reason, not a panic.

## Data

`Function { name, address, size }`, `ElfImage { path, symbols, span }`,
`AddressHit { address, text, byte_offset }`, and the existing
`SourceLocation { file, line, function, address }` from `bforge-dissect`.

Dependencies: `object` for symbols, `addr2line` with its `loader` feature for the
line table. Both are pure Rust, so this builds where no C compiler exists.

## Measured

28 October 2026, Windows. The image is this example's own debug build, because
there is no firmware `.elf` on this machine; a real run points at the firmware and
the code path is identical.

```text
image ...\debug\examples\s12_elf.exe: 19912 function symbols, loaded in 118 ms
code span 0x140001000..0x1403d5ee0, line info: present

input  HardFault: PC: 0x140001434 LR: 0x140001604 SP: 0x20004ff0 CFSR: 0x00000082
scan   4 pointer(s) in 30.2 us
  0x140001434 -> ...\core\src\slice\sort\shared\smallsort.rs:536
        code --goto ...\smallsort.rs:536
  0x140001604 -> ...\smallsort.rs:606
        code --goto ...\smallsort.rs:606
  0x20004ff0 -> no line information, show the raw address
  0x00000082 -> no line information, show the raw address

2 of 4 pointers resolved; SP and CFSR would stay as raw values

10000 lookups in 12.2 ms = 1.2 us each (10000 resolved)
```

Two of four pointers resolve, which is the right answer: `SP` and `CFSR` are data
and status, not code. 1.2 µs per lookup, so a screenful of a hundred badges costs
a tenth of a millisecond.

## A guard the tests forced

`addr2line` panics on `u64::MAX` with an integer overflow. A crash log can print
anything, so `resolve` now checks the address against the image's symbol span
before the lookup. The refusal is ours, the panic is not reached, and
`a_wild_address_resolves_to_nothing` holds the line.

## Test

```sh
cargo test -p bforge-elf
cargo run -p bforge-elf --example s12_elf
```

17 tests. Image: the test binary has function symbols, sorted; a symbol resolves
to a `.rs` file with a line; an address inside a function finds that function; a
wild address resolves to nothing; a missing file is named in the error; a file
that is not an image is refused. Scan: a fault dump yields its pointers, a 64-bit
pointer is found, short runs are ignored, wide ones are accepted, a run longer than
16 digits is refused, uppercase works, offsets and text are exact, and a line
without pointers yields nothing. Editor: both command forms, quoting, and the name
parser.
